# Spike S5 (Vercel) answered from Vercel's documentation

The question (`docs/evidence/day6e/spikes.md`, "S5: Vercel"; Day 7 plan section 2 security item 7): does the platform
overwrite `x-forwarded-for`, does `x-forwarded-host` pass through, do POST bodies stay out of runtime logs, is a
Firewall rate-limit rule free. Answered 16 Oct 2026 through Context7 (`/websites/vercel`, Vercel's own documentation;
`vercel.com` itself does not resolve from this session). Haider's look at the preview (Day 8) confirms the two header
answers on the real deployment.

| Question | What Vercel's docs say | What it means here | Action |
|---|---|---|---|
| Is `x-forwarded-for` overwritten? | Request headers page, `x-forwarded-for`: "The public IP address of the client that made the request. If you are trying to use Vercel behind a proxy, we currently overwrite the `X-Forwarded-For` header and **do not forward external IPs**. This restriction is in place to prevent IP spoofing." `x-real-ip` and `x-vercel-forwarded-for` are identical to it. | The share routes' per-IP limiter (`src/lib/share/rate-limit.ts`, `clientIp`: the first `x-forwarded-for` address) gets the real client address on Vercel; a client cannot pick its own bucket. The database's per-link limits stay the real guard either way | None. Keep the "unknown" fallback for non-Vercel runs |
| Does `x-forwarded-host` pass through? | Request headers page, `x-forwarded-host`: "This header provides the same host value as the standard host header." | Set from the request's host by the platform, not a client value passed on. `assertSameOrigin` (`src/lib/http.ts`) compares `Origin` with it; only browsers are what that check stops (they cannot set `Origin` or `x-forwarded-host` across sites), and the share routes carry no cookie | Day 8, Haider: on the preview, send `x-forwarded-host: evil.example` with `Origin: https://evil.example` to `/api/share/view`; expect 403 (numbered steps on Day 8) |
| Are POST bodies in runtime logs? | Runtime logs page: runtime logs "include all logs generated by Vercel Functions invocations … the output for your functions as well as the `console.log` output"; each line is application output, grouped per request with method, path and status (logs API fields `requestMethod`, `requestPath`, `responseStatusCode`, `message`). Retention: Hobby 1 hour, Pro 1 day | Bodies are not logged by the platform; only what the app writes to standard output is. The app writes nothing: ESLint `no-console: error`, 0 console calls in `src` (checked again 16 Oct), constant error codes in answers | None. Item 11 stays "no app logging at all" |
| Is a Firewall rate-limit rule free? | WAF usage and pricing: "Vercel Firewall features available on all plans are free to use. This includes DDoS mitigation, IP blocking, and custom rules." Rate limiting is a priced WAF feature: Hobby 1 rate-limit rule per project with 1,000,000 allowed requests included (and up to 3 custom rules); Pro 40 rules, usage-based at 0.50 USD per 1,000,000 allowed requests; keys IP or JA4, fixed window 10 s to 10 min | One rule on `/api/*` and the sign-in pages keyed by IP fits the Hobby allowance; on Pro at TopStock's volume (three people, a few thousand requests a day) it costs cents a month | Day 8 after the Pro upgrade (residual R1's later layer): Haider adds one rule, numbered steps given then |
