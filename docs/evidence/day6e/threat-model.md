# Day 6e threat model: the client stock link (design section 9, P1 to P16)

Each row: the threat, the control as built, and the passing checks that prove it. "attack" is
`supabase/tests/share_attack.sql` (CI job `db`), "conc" is `supabase/tests/share_concurrency.sh`, "unit" is
`tests/unit/share.spec.ts` or `tests/unit/proxy-share.spec.ts`, "e2e" is `tests/auth/share.spec.ts` (Chromium here,
WebKit in CI), "mut" is a mutation row in `mutations.md` that fails those checks when the control is removed.

|---|---|---|---|
| P1 | Guessing or enumerating tokens | 256-bit tokens made by the guard; lookup by `sha256` only; one answer (`{"status":"inactive"}`, HTTP 404, the same sentence) for malformed, unknown, revoked, expired, sharing off and lead deleted | attack `share_view_inactive_cases_same_answer` (byte-identical jsonb, also `share_request`); e2e `share_public_unknown_revoked_same_page_and_rep_cannot_create`, route guards (unknown token 404 `{status: inactive}`); mut 39, 40 (four rows) |
| P2 | Token leaks (logs, Referer, unfurlers, API logs) | Token in the URL fragment only; POST bodies; `Referrer-Policy: no-referrer` on `/s` and `/api/share`; `referrerPolicy: "no-referrer"` and `credentials: "omit"` on the page's fetches; VOLATILE functions (PostgREST serves them on POST only); the shell carries no data | e2e `share_public_lists_…` (no request URL contains the token), `share_public_headers_and_robots`; route `GET /api/share/view` → 405; attack `share_functions_volatile`; mut 46 |
| P3 | A forwarded link | No lead data on the page (only the creator's first name); expiry (90 days by default, 366 at most); revoke (no code); Replace; opens and requests counted for the team | attack `share_view_payload_keys_exact`, `revoke_is_permanent`, `replace_revokes_old`; e2e revoke then the same inactive page; mut "A revoked link may be brought back" |
| P4 | Token stolen from the database or a backup | Only `sha256(token)` is stored; `token_hash` has no grant for `authenticated` and is hidden in the audit | attack `token_hash_not_readable_by_authenticated`, `token_hash_not_in_audit`, `share_view_rejects_hash_as_token` (hex and base64url spellings); e2e: the audit holds no token; mut "The audit keeps the token hash" |
| P5 | Weak tokens planted by an insider | The guard makes the token on every insert, also past the grants; clients cannot name `token_hash` | attack `share_link_client_token_hash_ignored` (column grant, and a planted hash replaced for a maintenance insert), `share_token_format`; mut 47 and "authenticated may insert token_hash" |

| P8 | Another organisation | The link's organisation sets `share_org`; org-bound policies on products, levels, places, settings | attack `share_rls_org_setting_scoping` (no setting reads nothing; another org's setting shows only that org), `share_cross_org_never_returned`; mut "share_reader reads every organisation's products" |
| P9 | Lead data or other clients | No grant on companies, contacts, deals, orders, holds, profiles, tasks, the ledger or the audit; the signature is a snapshot of a first name | attack `share_reader_no_lead_columns` (12 reads refused) |
| P10 | Request spam or flood | Zod (route) and text pre-checks (function) with one "invalid"; 16 KB body; honeypot and 2-second time trap (fake "received", no database call); same Origin; 5 requests an hour and 20 a day a link, 200 a day an org, 10 new a link; one open task a lead; idempotency key | attack `share_request_payload_limits` (24 bad shapes and an over-16 KB note), `share_request_rate_limits` (6th an hour, 21st a day, 201st an org-day), `share_request_too_many_open`, `share_request_idempotent`; conc `share_request_parallel_one_task`, `share_request_parallel_over_cap`; e2e route guards (honeypot, fast submit, Origin, 415, 413, 21 lines); mut 41, 42, 51, "No limit on new requests a link", "… written twice" |
| P11 | Denial of service, free-tier exhaustion | Malformed tokens read nothing; unknown ones are one index probe and write nothing; over a limit nothing is written; 2,000 items at most after the in-stock filter; "unchanged" polls (about 100 bytes); positional arrays (2,000 items: 125 KB raw, 12 KB gzip); kill switch; per-IP limiter on each instance | attack `share_view_rate_limited`, `share_view_over_limit_writes_nothing`, `share_unknown_token_writes_nothing`, `share_view_2000_items_not_truncated`, `share_view_unchanged_version`, `kill_switch_disables_all`; conc `share_view_parallel_counters`; perf I9 to I11 (`perf.md`); unit rate limiter; e2e `share_public_rate_limit_message`; mut 43, 44 |
| P12 | XSS through names or request text | React text only (no `dangerouslySetInnerHTML`); safe-text checks on every client field (no control, zero-width or direction characters, no lone surrogates); share CSP `default-src 'none'` | attack `share_request_bidi_refused` (bidi, controls in note and name); unit schema refusals; e2e `share_public_xss_name_is_text` (a product named `<img src=x onerror=alert(1)>` renders as text, no `img[src=x]`) |
| P13 | Clickjacking, indexing, caching | `frame-ancestors 'none'`; `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet` and meta robots; `/robots.txt` public with `Disallow: /`; `Cache-Control: no-store` | e2e `share_public_headers_and_robots`; `headers.txt`; unit (proxy) share CSP |
| P14 | Session confusion (a teammate opens a link) | The proxy returns before any session code on `/s` and `/api/share`; the server's anon client has no cookies and no session; the functions are not granted to `authenticated` | e2e `share_public_signed_in_teammate_still_anon` (no `Set-Cookie`, no app chrome); unit (proxy) share branch without cookies or redirect; attack `share_view_not_granted_to_authenticated`; mut 45, 48 |
| P15 | The page's bundle or HTML exposes Supabase or internal words | ESLint `no-restricted-imports` (no `@supabase/*`, `@/lib/supabase/*`, `*-server` in the share page and components); the share message subset; a hand-written wire check (no schema library) | `bundle-scan.txt` (no Supabase, REST, cost or minimum-price string in any `/s/fr` script); unit `share_messages_subset_exact`; e2e `share_html_has_no_internal_strings` |
| P16 | Surface-header spoofing | The proxy deletes incoming `x-topstock-surface` and `x-topstock-locale` on every path before setting them for `/s` only; request config honours only the exact value | unit `spoofed surface headers are dropped outside the share paths`, `surface_header_ignored_outside_share`; mut 52 |

Also proved for the team side: `create_link_needs_editor_and_fresh_code` (rep on another lead, stale code, aal1,
another org's lead, bad language, 367 days, a bidi label), `expiry_bounds_and_extension_needs_code`,

fresh code), e2e `enable_sharing_needs_admin_fresh_code` and `share_link_create_needs_code_and_shows_once`.

## Accepted residuals (design 8.7)

- A direct PostgREST caller bypasses the Next layers (Origin, honeypot, time trap, per-IP limiter); the database limits
  are the real guard and hold on both paths.
- A flood of well-formed unknown tokens costs one index probe each and writes nothing.
- Vercel's request logs keep client IPs for their retention period; nothing is added to them (no `console` in the share
  code, ESLint).
- Splinter's `anon_security_definer_function_executable` WARN on `share_view` and `share_request` is accepted with this
  section as the reason (as `set_user_role`'s WARN was).
