### Screen readers: model (b)

- Recharts 3's `accessibilityLayer` makes the `<svg>` itself the chart's one tab stop (`role="application"`,
  `tabindex="0"`; read in `node_modules/recharts/es6/container/RootSurface.js`). So, as the brief says for that case,
  the svg carries the chart's `aria-label` (from messages, "Calls chart. Arrow keys move through the days. The same
  numbers are in Show as table.") and `aria-describedby` = the figcaption, and every layer inside it and the tooltip
  beside it are `aria-hidden`. A `MutationObserver` keeps that true when Recharts redraws. Nothing focusable sits inside
  `aria-hidden`: axe `aria-hidden-focus` passes, with a tooltip open too.
- The mini charts set `accessibilityLayer={false}` and are hidden whole; their numbers are in the Calls table.
- The figcaption and "Show as table" are the screen-reader path; the tables hold the charts' numbers (checked in e2e).
- Cards set `aria-busy` during a refetch; the "Updated HH:MM" line is `role="status"` `aria-live="polite"`.

### Security

- Product, file and person names reach the screen only as React text: table cells, tooltips (a component returning text
  nodes), and Recharts tick formatters that return strings (cut by characters). No `dangerouslySetInnerHTML` anywhere
  (unchanged rule, nothing added).
- Keys never come from names (products are keyed `p0`…`p9`).
- The browser sends only the canonical filters (`range`, `from`, `to`, `rep`, `idle`) to the P1 route, which parses them
  strictly; nothing user-typed reaches a filter string.
- e2e: a product named `<img src=x onerror=alert(1)>` shows as literal text in the caption, the axis tick, the tooltip
  and the table; no `<img>` in `main`, no dialog, no console error.

## Deviations from the design, with reasons

1. **Cache key `['analytics', canonical query string]`, not `[from, to, rep, idle]`.** The browser never does calendar
   arithmetic (design 2), and the dock must prefetch the default view without knowing its dates. Presets travel by name;
   the default preset and default idle days are left out, so the dock's `""` and a bare `/analytics` share one entry.
   A day change is covered by the 60 s `staleTime`; each answer carries its own `from` / `to`.
2. **The first-view flag is Analytics' own module flag** (`analytics-view.tsx`), passed through Home's
   `FirstVisitContext` to the same `CountUp`, instead of editing Home's `count-up.tsx`: Home's code stays untouched.
   Rule: first view of Analytics in the tab; after a client navigation always, on a hard load only when hydration came
   within 800 ms (Home's D29).
3. **A failed filter change shows each card's error, not the previous view's figures** (except a 429, which keeps the
   old frame by design). Otherwise a 500 would silently leave 30-day figures under a "7 days" button.
4. **The stacked Calls column is one Recharts `Bar` (the total) with a custom shape** that draws the reached part, the
   2 px surface gap, the 4 px rounded top and the busiest bucket's label, instead of two stacked `Bar`s: it keeps the
   gap, the radius and the label exact when either part is 0.
5. **English dates are US-ordered ("Oct 13")**, as everywhere else in the app (locale `en`); the design's examples were
   written in day-month order.
6. **Home, Leads and Pipeline JS grew by under 1 KB gzip** (bundle section): the dock's delayed analytics prefetch.
7. **axe runs on `main`.** On the whole document it reports `aria-hidden-focus` on the dock's bead
   (`data-testid="dock-bead"`: `aria-hidden="true"` with `tabindex="0"`). That is the shell's, unchanged by this work, and
   is left for a separate fix.
8. **Heatmap tooltips follow the keyboard and the mouse only**; a tap on a phone fills the readout line (design 4.2),
   so no tooltip covers the grid on touch. The volume metric has no hatched cells (a count is never misleading); the
   "N calls outside 07:00–20:00" footnote reads "Includes …" because those hours are shown (widened).
9. **`shell.spec.ts` on a fresh local stack.** The Analytics specs (alphabetically first) move their users out of the
   default org, so a later spec's first user becomes that org's admin, as before them. Run alone on an otherwise empty
   stack, the shell user became admin and its French command-menu test found "Importer des prospects" first; with an
   admin already in the default org (as in CI's run order) all 21 pass. No product change.
10. **`phone_fit` runs `/analytics` on the phone spec's Home-fixture org** (few calls, so the heatmap shows its empty
    line there). The filled heatmap at 390 (326 px, 44 px rows, readout, no sideways scroll) is checked in
    `analytics.spec.ts`; design 4.2 puts phone_fit on the filled page in P3.
11. **Not run in P2** (design: P3): the `/apple-design` and web-design-guidelines audits, `/security-review`, the
    advisor subagent, `analytics-perf.spec.ts`, and WebKit. The bundle was measured from the build instead of the perf
    spec.
